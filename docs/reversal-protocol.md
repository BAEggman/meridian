# 내일의 반전: 사용과 측정

## 사용하는 순서

1. 홈에서 매일 반복되는 시작 신호와 선택적인 시작 시각을 정한다.
2. 시작할 때 예약된 첫 질문 또는 예정 복습부터 답한다. 2분은 착수 목표이며 짧은 세트 완료가 하루 목표 완료를 뜻하지 않는다.
3. 정답·힌트를 보기 전에 원답을 남기고, 정답 공개 후 고정된 원답과 비교해 채점한다. 구술 응답도 가능하지만 자가채점 기록이다.
4. 틀린 연결을 교정하고 다른 문항 뒤 다시 확인한다. 당일 재현은 교정으로 남긴다.
5. 날짜를 넘긴 첫 무힌트 검사에서 이전 실패가 성공으로 바뀌면 회복으로 확인한다.
6. 끝날 때 다음날 확인할 첫 질문을 예약하고, 선택적으로 다시 공부하고 싶은 정도를 0~4로 남긴다.

## 무엇을 구분하는가

| 기록 | 의미 |
| --- | --- |
| 처리한 항목 | 실제 응답한 고유 과제. 완전 암기 수가 아님 |
| 첫 무힌트 응답 | 해당 날짜·문항의 첫 응답이고, 힌트·선택지 인지에 의존하지 않은 회상으로 명시된 수행 |
| 지연 첫 회상 | 이전 학습 날짜를 넘긴 첫 무힌트 응답 |
| 당일 교정 | 같은 날 실패·노출 후 다시 맞힌 수행. 첫 정답률에 합산하지 않음 |
| 회복 | 과거 실패가 있고, 날짜를 넘긴 첫 무힌트 회상에 완전 성공한 항목 |
| 기존 숙련 | 기존 엔진의 서로 다른 3일 성공 지표. 새 회복·무힌트 지표와 동일하지 않음 |

필수 선택형 문제와 힌트 사용 응답도 학습 기록으로 보존하지만, 무힌트 자유회상과 같은 증거로 세지 않는다. 새 기능 이전의 기록에 없는 원답·힌트 상태는 추정하지 않는다. 분모가 없는 날은 0%가 아니라 미측정으로 표시한다. D+1·D+3은 이전 학습 날짜와 실제 첫 응답 날짜의 차이로 구별한다.

## 다음날 재검사와 첫 질문

실패한 문항에는 다음날 재검사를 남긴다. 같은 날 교정에 성공해도 다음날 검사와 과거 실패 근거를 지우지 않는다. 날짜를 넘겨 첫 무힌트 성공을 확인하면 회복으로 기록한다. 힌트나 선택지로 맞힌 경우에는 이 기준을 충족하지 않는다.

정규 복습, 다음날 재검사, 예약 첫 질문이 같은 문항이면 한 번만 출제한다. 밀린 검사는 사라지지 않으며 첫 질문 예약도 기한 이후에 이어서 사용할 수 있다. 후보에서 선택한 첫 질문은 해당 학습을 대신하지 않고 큐의 시작 위치를 정한다. 현재 허브의 목표는 경락 학습 가능 항목 1,198개로 계산한다.

## 첫 응답과 새로고침

정답·힌트 공개 전에 입력한 원답을 고정한다. 입력, 힌트, 선택, 정답 공개 상태와 응답 ID는 중단 세트에 보존한다. 정답을 본 뒤 새로 시작한 세션에서 그 문항을 다시 맞혀도 그날 첫 무힌트 성공으로 바꾸지 않는다. 같은 응답 ID를 다시 저장해도 시도 수·시간·회복이 중복되지 않는다.

첫 응답과 실패 원답은 최근 스냅샷으로 보존하며 긴 원답에는 길이 제한이 있다. 각 재시도의 전체 글을 무제한 복사하지 않는다. 원답과 공부 기록은 현재 브라우저에만 저장한다.

같은 응답의 별도 중복 색인은 기존 이력으로 확인하며, 최근 7일을 지난 완료 응답의 중복 관찰 정보는 수치 요약으로 보관한다. 학습 이력, 최근 원답·실패 원답, 과거의 수행량·정답률·교정·회복·시간과 모르는 확장 필드는 보존한다. 브라우저 저장 한도는 사용 환경과 다른 학습 도구의 기록량에 따라 달라지므로 백업을 계속 사용할 수 있게 한다.

## 시작과 7일 관찰

대시보드에 방문한 것만으로 공부를 시작했다고 기록하지 않는다. 실제 첫 응답 행동에서 시작을 기록한다. 시작 시각을 설정하지 않았다면 지연 시간은 미측정이다. 같은 날 여러 번 시작해도 첫 시각은 바뀌지 않는다.

7일 표는 고유 수행량·첫 회상·교정·회복·응답 시간·재방문 의향을 따로 보여 준다. 응답 시간은 입력·선택·구술 시작부터 채점까지의 시간으로, 정답 공개 후 비교·교정도 포함한다. 화면을 숨긴 시간은 제외하며, 착수 전 문항 읽기·다른 도구에서의 학습·별도 그림 학습·휴식까지 자동 측정한 전체 공부 시간은 아니다. 관련 지표를 공부 효과의 인과적 증명이나 시험 성적 보장으로 해석하지 않는다.

시작이 쉬워져도 미완료가 늘면 실제 가용 시간과 잔량을 다시 확인한다. 기록 자체가 부담이면 선택적인 회고를 생략할 수 있다. 최소 행동에 복귀했다고 하루 전체 할당을 완료 처리하지 않는다.

## 저장 호환성

- 기존 `meridian_exam_v1`, `meridian_exam_session_v1`, 버전 1 백업 형식을 유지한다.
- 새 시험 상태 안에 `reversal`을 추가하며 기능 스키마는 `featureVersion: 1`이다.
- 모르는 필드와 카탈로그에서 사라진 카드의 기존 기록을 보존한다.
- 잘못된 값과 미래 날짜 기록은 보수적으로 격리하며 새 성공으로 승격하지 않는다.
- 백업에는 새 시험 기록도 포함된다. 복원은 기존 정책대로 중단 세트를 비우고 검증된 시험·기존 도구 기록을 복원한다.
- 브라우저 내부의 시험 상태만 무손실 압축하며, 기존 일반 JSON 저장값을 계속 읽는다. 내려받는 백업은 압축하지 않은 버전 1 JSON이다. 압축값을 읽지 못하면 원본 보호 모드로 남겨 덮어쓰지 않는다.
- 압축을 지원하지 않는 이전 코드로 되돌리기 전에는 현재 화면에서 일반 JSON 백업을 내려받고, 되돌린 뒤 복원한다.
- 저장 공간 오류는 화면에 알린다. 로컬 브라우저 기록은 기기 간 자동 동기화되지 않는다.

## 순수 엔진 API

기존 `review`, `getPlan`, `buildSession`의 계약을 확장한다. 다음 API는 입력 상태를 변경하지 않는다.

| API | 역할 |
| --- | --- |
| `getReversal(catalog, state, today)` | 오늘 첫 질문·예약·재검사·다음날 후보·최근 7일 지표 조회 |
| `reserveFirst(state, cardId, options)` | 내일 첫 질문 예약 또는 해제 |
| `setReversalPreferences(state, values, options)` | 시작 신호·계획 시각 저장 |
| `recordStart(state, options)` | 당일 최초 실제 착수 시각 기록 |
| `recordReflection(state, options)` | 선택적 재방문 의향 저장 |
| `recordExposure(state, cardId, options)` | 해당 날짜 최초 정답·힌트 노출과 응답 ID 보존 |

`review`의 추가 옵션은 `unaided`, `usedHint`, `originalAnswer`, `attemptId`다. 호출자가 첫 응답 여부를 덮어쓰는 대신 엔진이 날짜·문항·노출·응답 ID로 판정한다. 같은 응답이 자기 채점을 위해 정답을 공개한 사실은 정답 공개 전의 회상을 무효화하지 않지만, 그 뒤 다른 응답을 시작하면 첫 무힌트로 다시 세지 않는다.

검증은 `node tests/reversal.test.cjs` 및 기존 엔진·통합 smoke에 포함한다.
